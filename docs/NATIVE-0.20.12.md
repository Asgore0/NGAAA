# NGAAA 0.20.12

> 历史／来源文档：保留原版本的实现说明和验证边界，不代表当前候选重新验收。原始设备附件未随源码公开；当前状态见[文档索引](README.md)。

本版聚焦保留登录状态且应用缓存完全未命中的首次板块打开。

- `NgaStore.captureCheckInSession` 始终真实读取凭据，并在读取前后的权威加密值与域名相符时，同时填充只包含派生所有权的快照。`loggedIn` 使用这一快照；网络凭据没有新增全局明文缓存。失败读取不缓存为成功，账号、令牌或域名变化与持久写入回滚仍重新核验。
- 密钥正常存在时直接使用 `KeyStore.getKey`，省去每次解密前重复的 `containsAlias` 查询；只有未取到密钥才检查别名，已有非密钥条目或异常不会被覆盖。仍每次从系统密钥库取句柄，不缓存明文或密钥句柄。接口行为依据 [Android KeyStore 文档](https://developer.android.com/reference/java/security/KeyStore#getKey(java.lang.String,%20char%5B%5D))。
- Activity 初始化捕获的同一次会话复用于头像来源；首个板块请求仍在工作线程重新捕获真实凭据。初始 `onResume` 不再无条件清除刚创建的派生快照，后台停止与销毁仍清除。
- 保留原有的签到、通知、云屏蔽与云收藏启动顺序及并行网络请求。对照发现把全部自动请求延后到首屏，会在本模拟器环境稳定暴露约半秒 TLS 握手等待；该实验方案已撤回，不进入发布包。
- 首屏绘制后的异步回调重新核对页面、代次和会话，首屏前刷新同一板块时仍观察有效的新内容。

本轮保留 c2 延后方案、c3 恢复并行方案和 c4 初步复用方案的原始对照记录；c4 完整对照未证明首屏加速，后续继续削减密钥查询。诊断支持“回退主要落在 TLS 握手等待”，不能据此断定服务器或模拟器的具体原因；没有更改 TLS 校验、发送人为预热请求或关闭正常自动功能。

## 验证口径

本轮原版与新版均使用完整正式 APK、模拟器中已有登录账号。每样本结束进程并仅清空 `/data/user/0/cn.ngapure.app/cache`，保留偏好、账号与 Android Keystore；不重置系统、DNS、ART 或服务端缓存。

首绘测量期间仅轮询 `--startup-state` 的数字分段信息，避免完整 `--ui-state` 自身的登录态读取干扰。首绘完成后才验证实际登录、页面 `source=network`、单次板块请求和自动同步恢复。主要指标使用应用内记录的 onCreate 到首次内容 OnDraw 纳秒偏移；外部 ADB 观察时间单独保留。首绘不代表全部图片下载或 GPU 已显示。

真实已登录的采样 trace 与未跟踪的对照分别进行。采样只有方法名和时间，不采集方法参数、Cookie、账号标识或响应正文；采样区间交叠只能证明并行，不能直接换算成精确锁等待时间。新增读取诊断仅计数和纳秒；解密耗时包括编码解码、Keystore 和密码操作，不包括进入同步方法前的等待。

离线状态机、账号隔离及 Android 自己 UID 下的合成凭据 Keystore 测试用于功能回归；不把这些合成数据当作真实登录的性能结果。独立源码包排除签名私钥，使用外部同一签名重建并校验程序内容。
