# Android 0.11.0

> 历史／来源文档：保留原版本的实现说明和验证边界，不代表当前候选重新验收。原始设备附件未随源码公开；当前状态见[文档索引](README.md)。

这轮检查了页面导航、网络传输、缓存、图片与富文本、登录状态、签到、草稿和社区功能，并优先修复能由代码和回归测试证明的问题。保留原生界面、单层液态玻璃底栏和现有账号，不引入广告、统计或开发者服务器。

## 已完成的优化

- 页面读取与提交操作使用不同的执行器。离开页面取消旧读取、清除等待任务，并在后台主动关闭对应连接；快速切页不继续积累过期页面。取消执行器有界，极端饱和时仍以原有网络超时和 finally 清理作后备。发帖、收藏提交、图片导出和签到不会因普通切页被取消或重试。
- 每次网络请求固定起始 Cookie，重定向中不切换身份。首页缓存按域名和会话摘要隔离，主动刷新作废此前请求的缓存写入；摘要只存在内存中，不输出凭据。
- 首页缩略图和正文图片按视口加载，移除重复的首页图片线程池与缓存。普通媒体最多24个待处理请求，共享图片队列最多48项。正文图片滚离预加载范围、或缩略图与正文脱离页面时取消未完成请求，迟到回调不修改旧界面。GIF 只在自身可见时播放；Android26/27保留首帧显示。
- 图片实际尺寸加载后，在用户没有继续滚动或改变窗口时校正当前文字锚点；避免正文突然向下跳。旋转后使用新的布局恢复阅读位置，搜索范围和评分分页分别保存位置；最多保留128个最近位置。
- 保存活动时将实际呈现的底栏标签与其滚动位置一起保存，避免快速切换期间旋转后把旧标签的偏移套到新标签。应用隐藏后清除玻璃背景快照，返回时重新采样。
- 富文本解析对未闭合 BBCode 分隔符避免重复全文扫描。合成畸形输入与旧版对比输出一致；单次主机 JVM 耗时对比不代表真实设备帧率提升。
- 修复旧式 HTML 响应中的 `__PAGE` 数字键兼容问题：桌面测试使用的 org.json 库接受未引号数字键，Android 的实现会拒绝，导致录屏时真实公开帖子页码读取异常。该页码对象改用独立的有界标量解析器，限制为8,192字符输入、16个键、单个字符串4,096字符，支持数字或引号键、整数与带转义的字符串，只处理数据，不执行 JavaScript 或改写帖子正文；拒绝重复键、函数、嵌套对象和无效页数。桌面 API 回归由90项扩充到117项并通过；Android JSON 差异探针已在设备通过，同一个首页推荐帖可读取20条正文与65页分页。
- 图形验证码刷新时先清除旧图片、答案和 ID；请求或原生解码失败不能再使用未显示的新验证码。登录失败说明保持可见。
- 本地收藏、历史保存规范化头像和明确的赞数状态。旧记录缺失字段仍显示未知，不伪造为零；数值是当时读取的快照。正文只提供净赞时继续明确标注“净赞”。

## 验证与边界

数字分页修复后的最终候选 APK 已重建、覆盖安装，并复跑离线回归和设备检查；结果见 [验证总览](VALIDATION.md) 与 `device-checks-0.11.0.json`。原生设备探针仅输出固定状态及几何计数；合成图片测试不发送媒体网络请求。公开阅读测试会访问 NGA 公开内容，且仅在原账号当天签到已确认、没有待恢复二维码时运行。

密码和 SMS 的真实正向登录仍未提交凭据或发送验证码；二维码授权、自动签到的历史记录保持原版本归属。本版会复验已保留的登录状态和自动签到配置，不将历史验收冒充重新登录。未真实发帖、上传附件、发送私信或改动云端收藏。

窄屏、展开尺寸和生命周期由 API35 模拟器验证，不能代表所有真机、铰链、Doze、厂商后台限制或 Android26运行验收。不承诺设备帧率、内存和流量固定提升百分比。

## 研究依据

图片缓存、生命周期释放与性能检查参照 Android 官方的 [内存管理](https://developer.android.com/topic/performance/memory/manage-app-memory) 和 [渲染性能](https://developer.android.com/topic/performance/issues/render) 指引；具体实现以本项目的回归结果为准。当前版本保持可离线构建的 Android framework 技术栈。
