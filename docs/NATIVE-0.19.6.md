# Android 0.19.6 原生客户端维护更新

> 历史／来源文档：保留原版本的实现说明和验证边界，不代表当前候选重新验收。原始设备附件未随源码公开；当前状态见[文档索引](README.md)。

版本 `0.19.6 / versionCode30`，包名 `cn.ngapure.app`，最低 API26，目标 API35。本轮从已发布的 0.19.5 继续排查阅读、窗口重建、异步任务和本机持久化。累计功能见 README；最终安装包、源码、设备测试与录屏的对应关系以随包验证报告为准。

## 表格与媒体阅读

- 原生横向表格按每个图片字符在实际文本布局中的位置判断横向可见性，不再把整个单元格可见等同于其中所有图片可见。完全移出视口的动图停止播放，远处列不提前下载；仍保留 320dp 预取与 640dp 回收裕量。普通纵向表格移到屏幕下方但仍在预取范围内时继续预取，动画只在实际可见时播放。
- 覆盖普通列、跨列单元格、LTR/RTL、反向滚动，以及图片正好处于行尾、后一个字符换到下一行的边界。跨行选择区域中的零宽轮廓和行尾补齐不再扩大图片的可见范围；布局缓存不强引用旧文本布局。
- 表格宽度来自当前测量约束，首次显示、折叠、分屏和窗口尺寸来回变化时不再沿用上次布局宽度。

## 私信、提醒与弹窗

- 私信编辑窗口退场后，普通入口和迟到的查找结果不能再打开清草稿或确认收件人窗口。选择收件人也检查所属编辑器仍有效、未关闭且会话一致。
- 核对私信的分页替换旧窗口，避免连续翻页堆叠弹窗；已经关闭的窗口不再构建迟到的正文和图片。
- 用户条目使用整行作为统一的点击与无障碍焦点目标，避免头像和用户名另形成过小的独立目标。回复提醒打开相关主题时保留服务端有效的 PID；缺失或非法 PID 仍走普通主题入口。
- 签名、关注、收藏夹等用户操作弹窗的只读加载使用独立取消令牌和队列任务，取消或离页后不再继续执行排队读取，运行中的只读连接可响应取消。已确认写操作沿独立路径处理。

## 登录方式与确认操作

- 账号密码、手机验证码登录方式在 Activity 重建后保留。状态只保存有界整数和完整会话的哈希，仅在原登录路线及同一会话恢复；密码、手机号、验证码和协议勾选均不保存、不恢复。恢复账号或短信方式不会先启动一次二维码请求。无效类型、越界值、不同会话及非登录路线会被拒绝。
- 用户操作弹窗已确认的写任务使用进程内独立有界执行器：一个工作线程、最多两个等待任务。Activity 销毁不再中断该执行器，也不会丢弃它已经接受的等待任务。队列满时明确提示本次请求未发出，恢复按钮与取消能力，要求重新确认，不静默丢弃、不自动重试。
- 已开始的操作继续收尾；旧窗口或账号变化后不展示过期结果。尚未开始的账号操作核对确认时捕获的会话。本机屏蔽和清空列表也绑定确认时账号，避免 A 确认后切到 B 而修改 B 的列表。
- 此队列只存在于当前应用进程，不保存待执行任务或凭据，不提供进程被结束后的续传或重放。它覆盖用户操作弹窗使用的写路径，不代表所有业务写都改为同一个队列。

## 保存失败与重复操作保护

- Android 的 SharedPreferences 在 `commit()` 返回 false 前可能已经更新进程内数据。草稿耐久保存返回 false 时恢复原草稿事务，包括因配额计划移除的旧草稿，仍拒绝发出发布请求。没有发出的请求不再被误记为发布结果待核对。
- 点赞、举报、投票等操作日志的准备或清理返回 false 时恢复原值。真正已经发出且结果不确定的操作仍保留保护，不能通过重试意外重复发送或反向切换。
- 未读基线写入返回 false 时恢复当前账号原有基线、状态及检查时间，随后成功重试仍可识别同一条新事件，避免把尚未提醒的事件当成已经处理。
- 回滚沿用现有单进程锁，避免另一实例的有效写入插入事务。验证覆盖真实目录写入拒绝，以及调用线程被中断导致真实 `commit()` 返回 false；不把任意异常存储提供者的所有行为等同于该返回值合同。

## 固定材质与验证范围

`GlassPanel.java`、`LiquidSelection.java`、`LiquidMotion.java`、`Motion.java` 与 0.19.5 完全一致。固定浅色/深色底材、单层导航和原有手势形变保留；不采样或更新页面背景。

本轮使用当前客户端的公开只读页面、独立 UID 且无 INTERNET 权限的 Android 辅助程序、合成协议和本地资源。新测试执行真实 SharedPreferences、Activity 重建、原生按钮、文本布局、动图解码及通知组件；本机保存失败只调整辅助程序自己数据目录的权限，并在 finally 中恢复。通知只属于辅助程序并在结束时清理。
