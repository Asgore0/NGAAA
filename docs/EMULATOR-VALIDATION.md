| 步骤 | 结果 | 证据边界 |
| --- | --- | --- |
| 安装与启动 | 新版启动时曾在 Decor 创建前查询 InsetsController 导致崩溃，修复后已实际覆盖安装并成功启动真实首页 | 修复经过实际安装启动验证，并不代表全部页面已验收 |
| 官方应用参照 | 官方 9.9.69 已安装，并实际捕获清洁首页、社区与抽屉 | 过渡页面、登录页和不可用的个人页不计为通过；不声称所有页面一致 |
| 用户扫码登录 | 本客户端 WebView 打开官方真实会话二维码，用户用手机已登录的 NGA 官方 APP 扫码并确认，授权成功 | 扫码和授权由用户执行，不保存密码；不是普通网址二维码 |
| 原生会话保存 | 客户端接收官方会话，本机 Android Keystore AES-GCM 保存，原生账号状态为已登录 | 不写入账号标识、Cookie、令牌或二维码 |
| 重启与覆盖安装 | 多次模拟器完整重启和覆盖安装后，会话仍已登录、自动签到设置保留 | 已实际验证会话与配置持久化，未据此推断跨日自然调度 |
| 自动打开补签 | 启用自动签到后打开应用触发补签，服务器明确返回签到成功 | 与本地状态变化、统计数字或任务启动分别核实 |
| 重复手动签到 | 服务器明确返回“签到已确认 / 今天已签到” | 已实际读取当日已签响应 |
| 后台强制启动与去重 | `cmd jobscheduler run -f cn.ngapure.app 26018` 返回 `Running job`；之后记录仍为手动签到 `2026-10-18 01:23:25`，未新增后台尝试 | 当日已签被去重；`Running job` 单独只证明任务可启动 |
| 重启后任务登记 | `get-job-state` 返回 `waiting` | 证明重启后已登记等待，不代表已经过 24 小时自然调度 |
| 浅深玻璃 | API 35 浅色、深色抽屉真实背景模糊与边缘效果可见，文字清晰 | 仅当前 API 35 渲染路径通过；低版本 CPU 回退未实测 |

## 尚未覆盖

本轮 API 35 模拟器结果不扩展为 Android 8 / 12、低内存 CPU 渲染回退或各厂商真机验收。24 小时自然调度、省电限制、过期退出与重新登录、实际发帖回复和附件上传仍须分别记录；重启后会话、设置和任务登记保留已经实际验证。完整后续清单见 [设备验收清单](DEVICE-TEST-CHECKLIST.md)。
