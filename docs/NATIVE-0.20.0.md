# NGAAA 0.20.0 楼主图集、列表排版与独立赞踩

版本0.20.0，versionCode34，包名cn.ngapure.app，沿用0.19.9签名与本机数据。最低Android8/API26，目标API35。此文描述实现范围；最终通过项以本轮候选对应的原始测试记录与交付报告为准。

## 楼主首帖图片集

列表仍最多显示3张缩略图。点其中任意一张进入同一楼主首帖的原生图片集，从对应序号开始，可左右滑动、使用上一张/下一张按钮或无障碍滚动操作，显示当前序号和可浏览图片数量。图片处于放大状态时保留图片自身的拖动与双指缩放，不把平移误当切图。列表标题与行的其余区域仍进入帖子。

- 缩略图数量不再限制图库只能浏览3张。元数据保留经首帖身份校验、正文规则认可和去重后的官方附件URL，最多64张，URL总长度不超过64Ki字符；不把回复图、引用、隐藏、加密或代码里的图作为楼主首帖图片。
- 图片计数基于本次可确认的首帖图片来源。达到URL数量/长度上限或内容提取受限时，明确显示“仅展示前 n 张 · 共 m 张”或“共至少 m 张”；主序号使用实际可浏览数量，不把截断列表冒充全部图片。
- 图片集状态只保存有限URL、当前序号、已知总数/截断标记与缩放位置；不保存账号凭据、像素或Activity对象。重建后恢复对应图片和视口。无效或越界的恢复值会被拒绝。
- 首尾拖动有边界回弹；快速反向、取消手势或打断松手动画时以现有偏移接续，页面关闭或账号/域名变化后停止旧图片请求和迟到回调。
- 图集复用匿名图片读取，不向图片域名发送账号Cookie。预览设置关闭、可见性调度、内存缓存与会话隔离沿用前版。
- 正文或其他入口打开的单张图片仍使用既有单图浏览器；本次完整图片集入口是列表中的楼主首帖缩略图。

## 列表信息布局

主题预览行去掉楼主头像和名字，保留标题、首帖缩略图、独立赞踩、回复数与时间。时间放在卡片信息区右侧，与回复数对齐；窄屏或大字号下把操作和右侧信息分行，避免挤压标题与图片。论坛主题、搜索、本机历史/收藏、云收藏和用户/关注主题入口复用相同的列表信息组件。正文中的楼主及各楼层用户资料仍按正常阅读显示。

## 独立点赞与点踩

列表和楼层使用两个独立原生按钮，分别展示“赞”和“踩”。只有服务端明确返回的支持/反对总数才显示为数字；只有净评分或某次变动量时显示“—”，不把净值拆成两个虚构的总数，也不再以“净赞”代替两个按钮。

- 点赞和点踩均先进入明确方向的原生确认窗口；取消不发请求，未登录时进入登录流程。
- 请求沿用官方主题/楼层推荐协议，向同一tid/pid发送value=1或-1，重复方向可由服务器撤销，选中状态只来自服务器确认的标志。
- 显式确认与后台排队后再次核对账号、域名和会话范围；关闭页面后不显示旧回调。同一目标排队合并，结果不确定时保留防重复保护，避免反复点击造成重复写入。
- 返回的净变动不当作独立总数。操作后重新读取页面/首帖元数据，按实际可确认的数据更新。

## 黑金图标与固定玻璃

应用图标恢复黑金设计方向，保持原生自适应图标、单色主题图标与静态回退。图标可编辑源和细节见ICON-DESIGN.md。固定玻璃背景和底部胶囊核心动画不因本次图集与赞踩改动而重新采样页面背景。

## 验证边界

本轮计划对最终候选运行工作树与源码独立回归、离线同签名源码重建、真实生产组件的图集触摸与赞踩Android夹具，以及专用模拟器浅/深色和窄/宽窗口的实际UI检查、原始录屏。候选冻结、运行结果、失败/修正历史和SHA绑定保存在交付报告中；在运行前不宣称这些检查已经通过。

合成赞踩夹具不访问真实社区，也不等同真实账号写入成功；实际服务器仍决定权限、次数和结果。公开帖图集受网络、首帖可读权限与附件可用性限制。模拟窗口尺寸不是实体折叠屏铰链测试，截图及抽帧不证明持续动画帧率。
