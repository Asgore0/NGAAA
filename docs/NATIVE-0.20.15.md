# NGAAA 0.20.15

2026-10-25，versionCode 49。基于 0.20.14，调整楼层赞踩交互并补充撤销响应兼容。

## 变化

- 点赞、点踩和再次点击撤销直接提交，不再打开确认或成功弹窗。提交中同时锁住两个方向，结果在原楼层显示；失败也在楼层内说明。
- 点赞接口显式使用 `__output=8` 请求原生 JSON，不再依赖 `raw=3` 默认的网页封套。撤销响应提供有效状态位时，允许提示和净值变化缺省；未知变化值不会当成独立点赞/点踩数量。
- 同一楼层的在途操作由进程内控制器管理，页面重开或 Activity 重建不会重复提交。旧账号或线路的结果不会更新新页面；切回相同会话时保留仍在进行的操作。
- 服务端确认后原地更新选中态并补读独立计数。页面读取与操作确认交错时，以读取版本过滤旧数字，不重建页面或清空阅读位置。
- 如果响应无法确认，仍阻止自动重发。楼层内的“已核对，解除保护”只清除本机保护，不发请求；下一次独立点按才会提交。这也适用于升级前留下的未知结果。

## 证据与范围

匿名协议检查不带 Cookie、操作名、帖子编号或方向：默认 `raw=3` 返回 HTML 外壳，加 `__output=8` 返回 JSON。官方页面脚本使用状态位表示增加或移除选择，并允许净值变化参与 JavaScript 的缺省数值转换。真实用户本次撤销失败的原始响应未取得，因此不能断言上述兼容缺口就是该次失败的唯一原因。

设备集成测试使用独立 UID、无 INTERNET 权限的测试包，加载未经改写的完整生产 JAR、真实 MainActivity 和合成响应。测试不操作真实 NGA 帖子的赞踩，也不等同于真实账号服务器验收。客户端覆盖安装保持原有签名；源码和 APK 均不包含设备中的账号、Cookie、私有数据或签名密钥。
