# First-page response cache contract

`ForumResponseCache` caches only canonical page 1 models, before user block filtering. The caller passes the complete `contentScope` digest (host plus full cookie/session), route key and parent board ID. These three identities must match exactly. Rendering must still validate the current screen/session and apply current user rules. A hit never changes the original load timestamp and never triggers background revalidation or replacement of visible rows. An expired or unavailable cache is a normal network miss.

The TTL is 30 seconds. Memory age uses elapsed realtime. Disk entries additionally require fresh wall time and the same actual boot identity (`Settings.Global.BOOT_COUNT`, with `/proc/sys/kernel/random/boot_id` fallback); absent boot identity permits memory caching only. Reboot, elapsed rollback, wall-clock rollback and future/expired timestamps reject disk reuse. This intentionally favors missing a cache over presenting a possibly stale response.

Each process shares cache state across Activity instances. Capture a `Ticket` before the read; refresh, mutation, logout and host/session changes call `invalidate()`. That increments the shared epoch and clears memory synchronously without disk, JSON or Keystore work. Pending invalidation blocks disk reads/writes and coalesces rapid clears into one worker rotation of a persisted random generation marker. Old tickets can never repopulate the new epoch. If marker rotation fails, disk remains disabled until a later invalidation succeeds. **If the process is killed before the asynchronous generation marker reaches disk, a restart may reuse the old generation for at most the remainder of the 30-second TTL.** No UI thread waits for this cache durability operation.

`storeAsync(...)` captures the load time when queued, then serializes on an independent single worker with a queue capped at six writes. Excess older queued writes may be dropped; caching is best effort. The caller must publish the accepted model as read-only (reader/navigation work uses a separate copy). The cache deeply copies every accepted input/output model, including votes and children; network timing fields are intentionally zero in cached copies. `trimMemory()` only releases memory and does not change age or retire disk. `awaitIdleForTests(timeoutMs)` is a worker-only fixture barrier; application flows never wait for cache writes.

Storage is `Context.getCacheDir()/forum-response-v1`, excluded from Android backup. `load` is read-only: a missing directory or missing/invalid generation marker immediately misses without creating, repairing or pruning anything before the network read. An independent Android Keystore AES/GCM key (`ngaaa_forum_response_v1`) encrypts canonical fields, not raw responses or credentials. Hashed filenames and authenticated additional data bind each envelope to its exact scope/route/parent key. No key material is derived from account credentials. Memory is capped at six entries / 1 MiB; disk is capped at six entries / 1 MiB of encrypted payload, with 256 KiB per envelope and oldest-write eviction. Corruption, unavailable keys or storage failure become cache misses; a successful memory copy may remain usable when disk fails.

Run `TEST_WORK_DIR=/absolute/fresh/directory tests/forum_response_cache/run.sh`. The test compiles the actual production class and dependent models with the Android API jar plus the pinned local JSON jar. Actual JCE AES/GCM, JSON serialization and file I/O are exercised. The only seams replace Android Keystore retrieval, clocks, directory and executors. It covers precise identity, deep copies, non-sliding TTL, clock/boot rejection, tamper/AAD checks, size budgets, rotation/inflight epochs, coalescing, queued-write age, and nonblocking invalidation while key retrieval is blocked. Fixtures contain synthetic data only; no network or ADB is used by this script.
