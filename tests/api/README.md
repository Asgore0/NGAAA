# API 解析验证

在工程目录运行 `bash tests/api/run.sh`。需要 Java 17、Android API 35 的 android.jar，以及首次下载测试依赖时的网络。可通过 `JAVA_HOME`、`ANDROID_SDK_ROOT`、`TEST_WORK_DIR` 指定本地环境。

脚本核验并使用固定的 `org.json:json:20240303` 测试库，SHA-256：`3cf6cd6892e32e2b4c1c39e0f52f5248a2f5b37646fdfbb79a66b46b618414ed`。依赖仅保存到 work/ 测试目录，不加入 APK；Android 应用实际使用系统 org.json。Html.java 也是 JVM 测试替身，应用使用 Android 系统 Html。

fixtures 保留 2026-10-18 实际匿名响应的字段、编码、楼层、分页和编号结构，替换用户名及大部分正文，删除无关用户资料、官网脚本与广告内容。截断样例是在该脱敏副本上主动删尾；原始服务器截断响应已在开发工作目录中单独验证。完整公开目录直接读取应用 assets/forums.json，不重复复制。SHA256SUMS 用来核验样例未变。

0.19.9 当前共 2,867 项离线断言，覆盖 GB18030 / 错误标注 UTF-8 时的回退、46 条主题、短帖 JSON、截断响应拒绝、官方 HTML 数据包内的 20 个楼层、作者与 PID、页码、20 条官方推荐、子版块与主题合集路由、HTTPS 域名边界，以及签到成功、当日已签、否定确认、统计数据与服务端错误。测试中用 Unsafe 绕过仅 Android 环境可构造的 Context，不用于产品代码。

其中目录专项 2,694 项断言验证本地官方快照的 674 行按规范路由去重为 658 个目的地：372 个普通版块、286 个主题合集，16 行是同一路由的重复入口。普通版块以 `fid` 为 `Forum.key`；合集以 `stid:<id>` 为 key，`fid` 留空，父版编号单独保存在 `parentFid`，打开时使用 `ForumRoute.fromKey(forum.key).withParent(forum.parentFid)`。声明了非法 `stid` 的行不会降级打开其父版块；普通编号、合集编号、可选父编号分别校验，也不会用目录的 `id` 字段替代实际路由。

目录保留首个有效入口的显示名与顺序，并合并同一路由的别名、分类和分组；新增 `group`、`searchAliases`、`aliases`、`categoryNames`、`groupNames` 只用于展示或搜索。列表是不可变快照，数量和文本有界。测试覆盖别名合并、集合与普通版块同号但不同路由、无父版合集、非法编号和数据类型、重复路由、搜索字段和代理对截断边界。目录仍读取应用自带的 `assets/forums.json`，没有新增联网依赖；这些元数据不改变子版块响应解析。

开发时先以未变更的真实公开响应验证读取解析，再生成可发布的脱敏样例；0.2.0 加入签到结果边界检查后，共 41 项断言通过；0.3.0 的最终重跑状态见 `docs/VALIDATION.md`。这些测试只验证解析。0.2.0 另在 Android 15 模拟器完成用户扫码登录、重启/覆盖安装后状态保留、补签成功、重复签到与同日去重，具体范围见 `docs/EMULATOR-VALIDATION.md`；发帖与真机厂商后台行为仍待覆盖。

0.19.9 新增 32 项首帖图片原生响应边界断言：校验返回 tid、显式第一页、明确首楼及作者；缺失首楼、重复首楼、回复页、错误楼层所属主题、未知正文类型和服务端权限错误均不把回复图当作首帖图。纯图片提取与有界元数据加载/缓存的另外 163 项断言位于 `tests/topic_previews/run.sh`。`tests/reliability/run.sh` 同时检查固定账号/域名快照、过期 scope 在联网前拒绝、取消和截断时不请求 HTML 回退。

0.20.9 目录解析对照对全部 658 个目的地、13 个公开字段（包括有序别名、分组/分类成员和搜索元数据）做规范化序列化，核验与冻结 0.20.8 使用同一 Html 测试替身生成的 141,277 字节输出及 SHA-256 完全相同。新增用例检查 info → infoS → infoL 回退、说明搜索信息、分类/分组 HTML 清理和空输入；调用计数验证完整目录只解析 989 个非空文本（7 个分类、16 个分组和 966 个条目字段），空值不再调用 Html。该计数是 JVM 替身调用数，真实 Android Html 输出和耗时由 work/native-v209-performance/catalog-parse-probe 的独立无 INTERNET 探针验证。

0.20.11 保留上述全部字段快照和语义边界测试，只更新过时的工作量断言：788 个严格字面文本跳过 Html，201 个带空白、实体等需归一化的文本继续解析。JVM 调用计数仅证明减少工作；真实 Android 文本语义由 `tests/catalog_literal_device` 的旧算法 oracle、完整 658 项字段对照和 UTF-16/空白/控制符/实体边界验证，不以此 Html 替身充当平台语义证据。

0.20.13 候选的主题列表解析在每次 `parseTopics` 调用内懒初始化一个日期格式器，同批数字时间复用；纯文本或无效时间不会创建格式器。实例不放入静态字段、不跨请求或线程共享，单条时间解析仍独立创建。`ForumTopicTimeTest` 用合成列表验证固定上海时区（包括历史夏令时）、跨日/闰年/2038 年与最大秒数边界，保留 `lastpost` 缺失与显式 null 的区别、非时间文本清理，以及数字溢出后的原文本回退。6 个线程同时使用同一个 NgaApi 解析 144 个不同排列的混合列表，逐项检查时间和顺序；默认系统时区在测试结束后恢复。此测试验证解析语义和线程隔离，不代替 Android 网络首屏实测或证明稳定提速。
