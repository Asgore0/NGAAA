# Public avatar and recommendation metadata

Run `bash tests/avatar/run.sh`. The tests use synthetic metadata and a verified test-only org.json dependency. They perform no network requests, account access or device operations. The UI and loader also require Java 8/API 35 strict compilation and device review.

The native implementation independently reads these public protocol formats; it does not include third-party JavaScript or decompiled APK code:

- [Official commonui avatar handling](https://img4.nga.cn/app_res/sync/common_res/js_commonui.js?5871374), `commonui.selectAvatar`, `avatarUrl` and `uid2path`: a real avatar field may contain a URL, a legacy face filename, `.a/UID_timestamp.ext`, or a structured list of candidates. The compact form expands under `https://img.nga.cn/avatars/2002/`, with the nine hexadecimal UID digits grouped in reverse three-digit blocks. An absent avatar never causes a guessed image URL. A visible positive, non-anonymous author can opt into the official public `ucp/get` avatar metadata lookup; only a returned avatar is normalized.
- [Official recommendation rendering](https://img4.nga.cn/app_res/sync/common_res/js_read.js?3587966), `commonui.postArg.arg` and `proc`: numeric `recommend` is a recommendation value, **not the number of positive votes**. The string form is `value,support,oppose`; only its explicit second/third fields provide positive/negative counts. Independent `score`, reply counts and unrelated rating fields are not substituted. The server's HTML fallback supplies the same tuple in scalar `postArg.proc` arguments. The parser reads only those scalar positions from script elements; it never evaluates JavaScript.
- [Official forum icon mapping](https://img4.nga.cn/ngabbs/nga_classic/js_default.js?9965017), `commonui.forumIcon`: only IDs and aliases explicitly present in the official mapping were added to the bundled catalog. `/ngabbs/nga_classic/f/7.png` and `/414.png` were checked as PNG responses. Guessed `/ngabbs/newstyle/ficon/...` paths returned 404 and are not used. Unknown icons remain empty.

The list endpoints inspected expose numeric `recommend` and often no author table. The official post renderer proves the scalar meaning only for post arguments; no equivalent score contract was established for list/editorial recommendation scalars. `VoteMetrics.topicFrom` therefore accepts explicit support/oppose tuples only, leaving scalar topic recommendations unknown for both likes and score. `VoteMetrics.from` retains the verified post scalar behavior. Lists make no per-topic content lookups. The Activity can explicitly enable bounded public author-avatar metadata lookups for visible positive authors; existing same-response avatar metadata is preferred and memoized. An already opened thread page may use one optional `postVotes(tid,page)` HTML request to supplement its positive counts after the body renders. It validates the read template, topic/page identity and official base URL before reading fixed scalar arguments; it returns only a `floor:pid` metadata map, never executes scripts and never requests once per row. Missing counts remain `点赞 —` rather than a fabricated zero. A thread's count is not silently reused for a list row.

`AvatarView` uses the owner's shared `NativeImages`, an explicitly labeled official default helmet for users, an initial fallback for unknown boards, and genuine returned images only. The default drawable is distinct from the personal bitmap and never counts as personal-avatar coverage. See `docs/DEFAULT-AVATAR.md` for its vector provenance. Avatar requests share the existing two-worker pool, deduplicate URLs, bound queued/running URLs to 24, limit each URL to 32 listeners and each decoded avatar to 256 pixels per edge / 2 MiB downloaded bytes. Only genuinely visible views subscribe; scrolling offscreen, window hiding, detach and rebind cancel subscriptions, queued futures and owned sockets. Temporary saturation retries instead of leaving a permanent placeholder. Generation checks and weak view references reject stale callbacks. Verified bundled board images use an exact official-URL mapping and the same bounded worker decode path, with CDN fallback if a local copy is unavailable. Existing full-image, animated-image and explicit export paths retain their decoding behavior.

The optional `NativeAvatarResolver` owns a separate two-worker pool, at most 24 UID tasks / 32 subscribers per UID, and a 128-entry in-memory LRU. Existing reply metadata can seed its cache without networking. Public metadata expires after six hours, absent avatars after two minutes, and transport failures after ten seconds. Both sources accept only positive canonical signed-32-bit author IDs, disable redirects, have no account-storage dependency, never persist profile data and validate the returned UID before extracting its avatar. `publicSource()` sends no Cookie or Authorization header. `sessionSource(host, cookie, stillCurrent)` uses an immutable snapshot supplied by the Activity for the same normal NGA profile read used by the native user page. It permits only `bbs.nga.cn`, `ngabbs.com` and `nga.178.com`, rejects malformed header values and checks the current session before connection, during reads and after parsing. Its Cookie is sent only to the fixed NGA metadata origin; redirects are never followed and image/CDN requests remain entirely cookie-free. The Activity replaces and closes the resolver on account/host/session scope changes to clear caches and pending callbacks. Anonymous and negative author IDs never query the source. The no-argument image loader used by synthetic device probes has no author source enabled.

`NativeAvatarResolverTest` checks parser and identity boundaries, async cache delivery, TTLs, duplicate subscriptions, cancellation, saturation recovery, LRU bounds and both actual transport implementations via an in-memory HTTPS fixture. Session tests cover trusted-origin-only headers, CR/LF and host rejection, expiry before/during/after a read, cancellation, and a rejected redirect even to an otherwise allowed image CDN. It makes no real network requests. Live public checks during 0.13 preparation found all 23 avatar fields empty in the selected logged-out JSON and HTML page; one initial positive public profile and three additional real positive post authors also returned empty avatars. These logged-out observations alone do not prove that users lack personal images. A separate existing-session native-user-page check confirmed a genuine displayed author photo, motivating the same-origin session source. Final installed-device evidence measures the new resolver separately. Real users without returned personal metadata keep the explicitly labeled default helmet.
