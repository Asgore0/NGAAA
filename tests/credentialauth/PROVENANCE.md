# Credential protocol regression provenance

The anonymous official source is [NGA's login page](https://bbs.nga.cn/nuke/account_copy.html). Its locally checked response is 127,840 bytes with SHA-256 `0caf297c02c609ebf8c1350d5d4f2bd368aa2033264e33ccefbb3e6c1d72fbad`; the latest anonymous recheck matched the existing cached source. Relevant source ranges are lines 2892–2910, 3003–3010 and 3037–3043. This provenance records protocol field names and flow behavior, without retaining account inputs or credentials.

The official flow can reject a phone-only SMS send with a username/UID error and ask for the account identity. Supplemental identity belongs to `smsloginsendcode`: `name` is the supplied username or UID, `type` is `id` for a numeric UID and otherwise empty, `checkto` remains the phone number and `checktype` remains `phone`. The subsequent `smslogin` request still uses the phone number as `name` with `type=phone`; a supplemental identity must not silently change that request shape.

The user-reported wording, “此账号不能仅凭手机号登录 需要输入 用户名或用户ID 后方可继续”, is a regression input, not a captured successful account response. Tests also cover the official `用户id错误` / `用户名错误` prefixes, case/whitespace/HTML presentation, and error text in `msg`, `message`, array `error[0]` or numeric-key object `error["0"]`. Only a rejected send with an empty supplemental account may become `ACCOUNT_REQUIRED`. Other errors, an already supplied identity, password login and SMS code submission retain their existing error handling.

All new regression responses are constructed inline through `Fake.raw`; no fixture file or source fingerprint was replaced. The regression checks exact send fields, preservation of phone-only SMS code submission, message fallback precedence, refusal to call an unacknowledged `code=0` send successful, absence of automatic retries, and the local cooldown after successful, rejected, malformed, unavailable or uncertain sends. The cooldown is a client duplicate-send safeguard of 15 seconds, not a claim about NGA's server policy. Its expiry is simulated by changing a synthetic owner's monotonic timestamp; tests do not sleep or send messages.

These 10 added scenarios perform no socket requests, access no account, send no real SMS and do not complete a real CAPTCHA. They verify synthetic protocol and state behavior; real password/SMS account success remains outside their evidence scope. Run `bash tests/credentialauth/run.sh` to obtain the authoritative scenario and assertion counts for the current source.
