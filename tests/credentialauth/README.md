# Native password and SMS authorization

Run `bash tests/credentialauth/run.sh` from the source project. JDK 17 and Android SDK Platform 35 are required. `TEST_WORK_DIR` may point to an independent directory; otherwise generated files stay in `.build/credentialauth-tests` and must not be included in source archives. The test-only JSON jar is SHA-256 pinned and never included in the APK.

All 29 scenarios / 138 assertions use synthetic in-memory responses. They check the current official public RSA key, randomized encryption, account type inference, image challenge binding and consumption, failed-refresh/decode invalidation and recovery, explicit phone verification, SMS ticket binding and resend limits, malformed/error responses, cancellation, host/cookie isolation, CAPTCHA resource restrictions, and matching-cookie `iflogin` verification after grant exchange. They neither contact accounts nor send SMS; they do not prove a fresh password or SMS login works on a real account.

The protocol was checked against the [official NGA login source](https://bbs.nga.cn/nuke/account_copy.html), fetched on 2026-10-18. A source digest and public-key fingerprint are in `fixtures/official-protocol-source.json`. The implementation uses `login`, `smsloginsendcode`, and `smslogin`; both passwords and SMS codes use the public RSA key, and a returned grant is redeemed through the existing strict exchange/verification path. A server refusal or unsupported security challenge remains a visible refusal.

The forum UI and password/SMS forms are native. The sole embedded web component is the official Tencent human-verification widget required before sending an SMS, following [Tencent's Android integration documentation](https://cloud.tencent.com/document/product/1110/49810). It receives no phone number, password, forum cookie, or QR authorization value. Its resource/navigation allowlist covers the official domains found in the current official `TCaptcha.js`; file/content access, mixed content, web storage, cookies and permissions are disabled. The three-field callback accepts only a valid success ticket/random pair or cancellation; the NGA server still validates the ticket. Nothing is automatically solved or treated as login success.

SMS sending requires an explicit user tap followed by successful official human verification. Passwords and codes are not saved into preferences, instance state, files, logs or diagnostics. Backgrounding or leaving the form cancels work and clears its inputs; a stale callback cannot replace the stored account. Only a current server-verified attempt may call `NgaStore.setCookie`. Existing QR authorization and its encrypted short-term recovery remain separate.

`NativeLoginView.dumpState` includes only `method=QR/PASSWORD/SMS`; credential diagnostics include `busy`, `challengeVisible`, `paused`, `closed` and `committed`. No form values or ticket values are exposed. To preview the official widget without any SMS flow, the integrating Activity can instantiate `new NativeCaptchaDialog(activity, callback)` and close it; that class itself has no phone field or NGA SMS/network method.
