# 原生二维码认证协议回归

在项目根目录运行 `bash tests/nativeauth/run.sh`。需要 JDK 17 和 Android SDK Platform 35；可设置 `JAVA_HOME`、`ANDROID_SDK_ROOT`、`TEST_WORK_DIR`。脚本仅在测试缓存中使用固定 SHA256 的 org.json 20240303，不会将测试依赖打入 APK。

这些测试使用合成二维码钥匙、合成 UID 和合成会话，覆盖等待、3 秒间隔、90 秒自动暂停与手动继续、过期、安全校验、同源 Cookie 交换、服务器会话确认、取消、刷新、重试及非法响应。恢复场景检查授权/兑换进度先持久化、旋转暂停交接、进程恢复后重新验证、不延长原自动轮询窗口，以及明确终态清理。fixture 中没有真实账号或授权凭据。测试不会联网、启动 App、访问设备或读取 NgaStore。

恢复存储测试使用内存存储、合成时钟和实际 JCE AES-GCM，验证密文、随机 IV、host/owner AAD、旧 owner 无法覆盖新授权、十分钟客户端恢复窗口、时钟异常、损坏记录及保存失败。生产路径用独立 Android Keystore alias 和应用私有 SharedPreferences；本地十分钟窗口不是 NGA 服务端二维码有效期。恢复记录不代替服务器授权，也不会从已有账号 Cookie 伪造 grant。

公开官方协议的匿名初始化和未扫码状态已探测，已有授权会话的兑换/确认组件也已实际核验。新二维码授权 → 兑换 → 验证 → 保存的正向链路，以及恢复后的真实扫码仍需设备验收；已有会话和本地合成 fixture 通过不能替代新扫码成功。
