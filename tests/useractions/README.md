# Native user actions

`./tests/useractions/run.sh` runs 163 synthetic wire/persistence/filter checks, including independent cloud state verification, missing relationship metadata, uncertain writes, account/host/cookie changes, stale folders, exact reply locators, signed avatar endpoint validation and failed local persistence. No live account, message, upload or network is used by the tests.

`NativeUserFilterTest` verifies that one captured host/account supplies both local and cloud rule stores, including a host preference mutation between the two reads. Each new capture sees rule additions/removals and account/host changes immediately; an existing render keeps its independent rule sets. Anonymous and corrupt caches do not hide unrelated content. The public anonymous path reads the encrypted-cookie source exactly once and never writes. The exact-session fixture overload preserves the original account parser; it is not a long-lived session cache. Real authenticated Keystore call counts and timings require the separate own-UID Android instrumentation probe, rather than these JVM fixtures.

The real UI sources are compiled by the application build. `NativeUserActionDialogs` uses the shared `NativeGlassDialog`, owner lifecycle handling, cancellable reads, retained busy confirmations, native signature/folder inputs, a system image picker callback and native drag/pinch avatar crop. It does not create WebViews or open a browser.

The official cloud protocol creates a folder while adding a post using `topic_favor_v2/add`, `folder=-1`, `tid`, `pid`; this implementation then sets the requested name/options with `modify_folder` and verifies both stages. It does not pretend an undocumented empty-folder endpoint exists. Rename, public/default flags and delete use the documented actions. A partially completed creation is reported explicitly and is never retried automatically.

NGA's cloud follow capability uses `follow_v2/follow`, type 1 to follow a user and type 8 to unfollow. Missing `ucp/get.followed` is resolved by reading the complete authenticated `get_follow` list through its explicit empty page, rather than being interpreted as false. Follow and profile writes are made at most once and require an independent readback before success is shown.

NGA cloud blocking uses `ucp/get_block_word` and `ucp/set_block_word` as implemented in official `commonui.blockword` (js_commonui lines 7217–7372). The complete version-1 document preserves both keywords and author tokens. Editors compare the original etag plus whole document before writing; stale editors do not overwrite another device. Single-user block/unblock preserves all other users and keywords. Independent full-document readback is required before success. The real read-only capability probe confirmed an empty string with numeric limit/etag is valid. `NativeUserActions.refreshCloudBlocks(context)` performs a worker-thread cloud read and updates an account/host-scoped local filter cache; it never writes the server.

The separate optional local block list remains explicitly labeled as local, scoped to SHA-256(host + account), with native list/unblock/clear/recovery. Old local blocks are never automatically uploaded. Call `NativeUserActions.filter(context)` once per render and apply `UserFilter.blocks(uid, username, rawContent)` to merge local UID blocks and the official cloud author/keyword cache. `sameAs` compares rules in memory without exporting author names, IDs or keywords. Server refusals for individual author-search rows are counted in `TopicPage.unavailableItems`, with other public rows retained and source pagination preserved. Native profile/favorite lists show unavailable notices and reversible local placeholders for filtered records.

No live production mutation was performed during implementation. Root integration/device validation must report read-only verification separately from user-authored writes.

Selected-folder removal now uses the official v2 `del` protocol with folder + exact tidarray + page, and independently reads back that same folder. The compatibility overload resolves explicitly to default folder 1. New NativeFollowingView reads official get_push_list events, and NativeActivitiesView reads get_event_app rather than deriving activities from recommended titles. NativeCommunityView provides a native username lookup/confirmation for private-message recipients and an explicitly enabled author-avatar source.
