# Cloud board favorites protocol

The anonymous official source is [NGA's shared UI script](https://img4.nga.cn/common_res/js_commonui.js), rechecked with a fresh anonymous GET on 2026-10-19 without cookies (`work/research/favorites-v16/commonui.js`). Its response is 217,550 bytes, SHA-256 `df484d53762b9b53bdf18e2108a7b5dbafccf44a8fdb985c98e4cd3d6a767e7a`, identical to the earlier local research copy. Only protocol field names and response semantics are used; no third-party UI or implementation is copied.

In its `hisLinkV2.merge` flow (UTF-8 source lines 8294–8351), the official script submits a read-only POST to `/nuke.php?__lib=forum_favor2&__act=forum_favor` with form fields `__output=3` and `action=sync`. `doRequest2` places the parameters following `u` in the request form. Its callback reads the collection at `data[0]`, iterating either array or object rows. A nonzero `fid` identifies a forum; otherwise the row's nonzero `id` identifies a collection (`stid`). Collection identity must not be confused with a parent forum's `fid`.

The same script's `save` flow (lines 8221–8241) separately uses `action=add` or `action=del` with `fid` or `stid` for remote writes. The new explicit `setDesired(key, desired)` operation uses that exact POST write shape: routing and `__output=3` in the URL query; the form contains only `action` and one of `fid` or `stid`. It does not use `topic_favor_v2`, which is the separate topic/reply-favorites feature.

`setDesired` first reads the current cloud membership. If it already matches the requested state, it returns `ALREADY_MATCHED` and sends no mutation. Otherwise it issues one write and, after an accepted or uncertain response, one separate read-only `sync`. Only a matching membership in that parsed snapshot returns `CONFIRMED`; HTTP 200, a generic success string, and arbitrary JSON alone cannot confirm a write. A missing or mismatched verification returns `UNCONFIRMED`, while explicit login, challenge, permission and rate refusals return `REJECTED`. There is no automatic write retry. A user-initiated retry again starts with a membership read, so an already delivered write is not duplicated. Preflight read failures throw before any write.

Each multi-request change captures one allowed host and valid account UID. Every request obtains the current cookie afresh and rejects a changed host or UID; no cookie is retained in the transaction or result. The UI separately serializes pending changes, retains unconfirmed intent and verifies its captured account scope before a local commit. Construction, reads, import and application startup never invoke `setDesired` automatically.

`CloudForumFavorites.read()` requires an existing complete login through `NativeCommunity`, uses its established HTTPS allowlist, bounded response decoding and legacy wrapper parser, and performs no retry or write. Returned metadata preserves stable keys: a forum's original `fid`, or `stid:<id>` for a collection. Missing names get explicit ID fallbacks. Invalid response structures fail atomically rather than becoming an empty successful import.

Local import is a pure merge of the request-start favorites `S0`, the current favorites `C`, and cloud identities `R`: `C ∪ (R − S0)`. It preserves current local entries and does not resurrect a favorite removed during the read. The UI must still verify its captured account/host/navigation/edit revision before persisting local results and metadata; the backend does not persist automatically.

All regression data is synthetic and inline. The 33 scenarios / 203 assertions verify exact sync and add/del wire shapes, positive and negative forum IDs, collection separation, metadata normalization, empty versus malformed responses, errors, legacy charset/wrapper handling, local merge behavior, idempotent retries, post-write read-back, unknown delivery and account/host changes between requests. Fake transport counts all reads and mutations; the tests perform no socket requests, account access, real sync or real remote writes. A real account's cloud contents are outside these tests' evidence scope.
