# Android Keystore and real-process cache probe

This separate, non-Internet Android package embeds the exact complete frozen production JAR without rewriting or shadowing product classes. Its build binding records the JAR/APK hashes. It uses its own UID, actual `ForumResponseCache(Context)`, actual Android Keystore key, and a private synthetic cache directory. It never launches the real client, reads a real account, or contacts a server.

Build with `PRODUCT_JAR`, `PRODUCT_APK`, optional expected SHA256 variables, `SIGNING_DIR` and a fresh absolute `BUILD_DIR` using `build.sh`. Keep signing material outside the source/helper archive. Output is `forum-cache-probe.apk`. The manifest and packaged permissions are checked to exclude INTERNET and shared UID.

Run instrumentation `cn.ngapure.forumcacheprobe/.ForumCacheProbe` with `mode=seed`, then force-stop only this helper and run `mode=read` promptly (under 30 seconds). The seed phase checks main-thread disk avoidance, main-thread synchronous-load rejection, asynchronous write completion, deep copies, real encrypted disk source, exact scope/route/parent/page identity, nonexportable Keystore key, absence of plaintext, GCM tamper rejection, and cross-instance invalidation. Its final operation writes the restart fixture and records the helper PID and frozen JAR hash. The read phase requires a different PID and identical JAR, verifies disk source, canonical fields and original TTL, then tests rapid invalidation and removes its synthetic cache data. A missing or expired restart fixture fails rather than silently reseeding. Both phases produce `safe_cache_report` and their own files-directory JSON reports.

The same-process `trimMemory()` disk check is explicitly separate from the PID-checked restart test. This probe does not measure real network latency; the MainActivity integration probe and anonymous network diagnostic probe cover those paths independently. The broader injected-clock boundary and adversarial bounds suite is in `../forum_response_cache`.
