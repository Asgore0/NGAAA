# Synthetic session reads on Android Keystore

This fixture embeds the complete immutable production JAR and exact public APK assets. It runs as `cn.ngapure.sessionreadsprobe`, without INTERNET or a shared UID, and never launches or reads the actual client. The manifest package query only permits comparing the two apps' public UID metadata. Its HTTP handlers also reject all requests.

Only fixture-created synthetic cookies are encrypted with the real production `NgaStore.setCookie()` and Android Keystore inside the fixture's UID. The probe compares credentials and ownership hashes internally; reports contain check labels and numeric counter deltas, never credentials, account IDs, scope hashes or ciphertext. The synthetic login is removed in `finally`; root should uninstall the helper after pulling its safe report.

Cases verify one fresh capture primes 100 repeated scope/login checks, three fresh worker captures still perform three decryptions, exact account/token/host changes, a separate store's independent fresh capture, two retries for bad Base64 and bad GCM followed by successful recovery, explicit background-style cache clearing, logout propagation, repeated logout and a new login. Decode timing includes the key-monitor wait and cryptography, but excludes source capture/revalidation. Separate numeric lock counters cover instrumented authoritative source reads only, not every monitor or account write. This is functional and operation-count evidence with real Android cryptography, **not a real logged-in user's startup or network latency measurement**. It does not claim actual Activity lifecycle exercise or a physical disk failure; the pure session/login-preference tests also cover their policy and rollback contracts.

The final cases delete only this fixture UID's cookie-key alias. A fresh credential read and a subsequent ownership read must both fail for the unchanged old ciphertext, discard the previously successful ownership cache and leave the encrypted preference untouched. Production may recreate the missing alias, but its new key cannot decrypt the old ciphertext. A new synthetic login must then recover normally. This case never deletes or inspects a key owned by the real client.

Existing-alias concurrency cases hold only this helper process’s `NgaStore.class` monitor and require four actual credential reads (same-store and independent-store variants) to finish before it is released. UI ownership/login and the authoritative source monitor must remain available. The monitor now protects only missing-key creation, so this intentionally replaces the c1 fixture’s expectation that a normal read blocks there. The exact c1 fixture, binding and execution evidence remain preserved under the c1 work directory.

Eight simultaneous first-use calls invoke the actual private production key accessor through reflection, without changing production fields or provider selection. Every returned non-exportable key must encrypt data that the final authoritative alias can decrypt; this detects duplicate generation that overwrites another caller’s key. Further cases replace the same alias with a different real Android Keystore AES key, and install a certificate-only entry. Old ciphertext must fail repeatedly without cached success or preference mutation; an existing non-key alias must never be replaced even by a login attempt. Explicit removal followed by a new synthetic login must recover. Earlier c1 mutation/rollback latch cases and pure scope races remain in their original evidence; these key tests do not claim to rerun those c1 gates. Deadlines are bounded deadlock/regression guards, not latency targets.

Build only after the production APK/JAR are frozen. Supply absolute `PRODUCT_JAR`, `PRODUCT_APK`, their independently recorded `PRODUCT_JAR_SHA256`/`PRODUCT_APK_SHA256`, an existing external `SIGNING_DIR`, and a fresh absolute `BUILD_DIR` to `build.sh`. The build rejects changed inputs, class shadowing, INTERNET, shared UID and stale build directories. `binding.json` includes all production class/public asset and fixture source hashes.

Root alone runs instrumentation, with `-e syntheticCredentialsOnly true` and component `cn.ngapure.sessionreadsprobe/cn.ngapure.app.SessionReadsProbe`. The sanitized result key is `safe_session_reads_report`; the APK is `session-reads-probe.apk`. No ADB command is performed by the build.
